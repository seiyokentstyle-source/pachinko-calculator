# PACHIEV

機種選択＋実測条件入力のパチンコ期待値計算機。EVOTの白基調デザインを使い、EVOT本体・探索ツールとは独立した静的サイトです。

- 公開先: https://seiyokentstyle-source.github.io/pachinko-calculator/
- EVOT本体: https://seiyokentstyle-source.github.io/ev-live/
- `main` へのpush後、GitHub Actionsが計算テストとJavaScript構文検証を行い、成功した `dist/` だけをGitHub Pagesへ公開します。
- 白基調・濃紺の文字・青い数値を使い、スマホは1列、広い画面は入力と結果を2列で表示します。外部フォント・外部スクリプトに依存しません。
- 「期待値・着席前・着席後」を切り替え、機種と貸玉条件を共通設定にしています。回転率の入力は「回転数・玉の出入り・当たり出玉」の3区分。長文の入力例・機種根拠は折りたたみ、下限表示・標準値の仮定・不足項目は残しています。
- 入力データは同じURLのブラウザ内に保存されます。Sites版とGitHub Pages版は別オリジンのため、以前の保存値は自動移行しません。キー名は互換性のため `tamayomi.*` を保持しています。

- `dist/`：そのまま配信できるHTML・CSS・JavaScript。外部依存なし。
- `node server.mjs`：ローカル表示（http://127.0.0.1:4179）。
- `node --test test.mjs spec-test.mjs session-test.mjs all-input-test.mjs before-seat-test.mjs`：交換条件・機種の状態遷移・独立した閉形式・実戦記録の玉収支・履歴集計・個別純増入力・着席前後の分離を検証。
- `npm ci` → `npm test`：上記86件に加え、jsdomで画面切替・保存復元・反映・貸玉変更・入力エラーへの移動の8件を検証。jsdomは開発時のみ使用し、公開ファイルには含めません。実ブラウザの描画検証とは別です。

`dist/machines.mjs` に6機種の振り分け・出典・資料確認日を登録し、`dist/spec-engine.mjs` で吸収過程の期待報酬を解きます。初当たりから通常復帰までの平均差玉を用い、固定通常回転数に対する期待収支を計算します。持ち玉使用割合は固定の外生入力で、持ち玉の推移や閉店終了はシミュレーションしません。

着席記録は `dist/session-calc.mjs` と `dist/session-ui.mjs` で計算します。自分の貸玉・再プレイ・開始/現在の持ち玉を使う方式と、台の開始/現在の差玉を使う方式を選べます。通常回転の累計差を使い、右打ちを含む総回転の場合だけ記録した右打ち回転を控除します。大当たりでリセットする現在スタートだけ、または差玉・当たり件数だけから通常回転を逆算することはできません。

通常回転数は直接入力も可能です。通常初当たりの全履歴と現在スタートがある場合は、`履歴の回転数合計＋現在スタート−着席時スタート` で集計できます。履歴は古い順で、通常開始から当選までの回転数（最初の1件は着席前分を含む）です。右打ち当たりを除き、通常からのチャージも含む全件がそろい、通常復帰ごとに0に戻る仕様であることを入力者が確認する必要があります。履歴なしは現在≥着席時、履歴ありは先頭≥着席時を検証。不足履歴を確率で推測したり、内部STの平均回数で補完したりしません。

期間差玉D＝現在持ち玉＋外へ移した玉−開始持ち玉−現金貸玉−再プレイ−受取玉。台差玉方式ではD＝現在差玉−開始差玉。当たり・電サポ中の純増Gを別に入力し、通常消費C＝G−D、回転率＝通常回転×1000円あたり貸玉÷C。実測Gを使う場合と、個別の払い出し区分の回数×標準差玉を使う推定を区別します。グラフ概数も推定扱い。初当たり平均連チャン出玉を実戦の当たり件数に掛けません。

`dist/session-prizes.mjs` の区分は実際に消化済みの出玉を重複なく入力する単位です。1500個×2回と3000個×1回を重ねません。310個のリコリコ3Rは一撃の一次調査による10Cを用い、310−30＝280玉。その他は既存機種の賞球・カウントに基づく標準差玉です。当たり差玉補正と電サポ増減0の仮定を明示します。計測期間・持ち玉の集計範囲を統一し、右打ち終了後に比較してください。短区間の実測は台の長期的な回転率の保証ではありません。

当たり内訳では、標準差玉を使う `netMode: standard` と、1回あたり純増を利用者が入力する `netMode: measured` を選択します。後者は回数が正の全区分で `unitNets` の入力が必須。標準値で空欄補完せず、標準出玉補正もかけません。別計上の電サポ増減を加え、純増に含めた場合は0を入力します。平均純増×回数は推定扱いのままです。区間全体の正確な純増が分かる場合は合計実測方式を使用。新規記録・専用リセット後の内訳入力は手入力を選択し、旧保存データには従来の標準方式を保持します。

実戦記録は `tamayomi.sessions.v1` に機種ごと保存し、別台への移動時は専用リセットを使います。期待値条件リセットとは独立しています。反映ボタンは丸め前の回転率を渡し、任意で通常回転数も反映。推定/実測入力の由来を期待値側にも表示・保存します。貸玉条件は主画面と共通で、持ち玉使用割合は自動推定しません。

着席前モードは、同じ台の同一集計区間の通常回転・差玉・当たり出玉から過去の回転率を推定します。財布方式を使用せず、`dist/session-context.mjs` で差玉方式に固定。開始値を自動0にせず、全区間が通常状態から始まり右打ち終了後まで揃うことが条件です。標準差玉の仮定、入力出玉、差玉の数値/概数、通常回転の取得方法を根拠として画面に表示し、根拠のない精度ランクや信頼率は付けません。

同じ保存領域で、既存 `records[machineId]` は着席後のまま保持し、着席前は `records[machineId + '::before']` に別保存します。保存済みモードがなければ着席前を表示します。リセットは選択中の機種×モードのみ。着席前の入力には着席後の保存値を流用しません。期待値へ反映した出所に着席前/後を明示し、過去の通常回転数を予定回転数へ適用する選択肢は既定OFFです。過去データからの値は常に推定扱いで、これからの回転率を保証しません。

牙狼12・結城友奈はメーカー公表フロー、東京喰種はメーカー公表値＋公開解析の上乗せモデルです。沖海6 Withえなこ（RBD）はメーカー公式リリースの1/99.9・1/9.9と賞球10を採用し、残保留4個を電サポ維持とは別状態にしています。解析資料の1/9.99との差も画面に開示します。

リコリスとSAOアリシゼーション夜空は、`dist/conservative-models.mjs` で公表・取材数値を固定したモデル内の保守下限を計算します。未公表の内部率を確定した期待値ではありません。両機種は `estimateKind: 'lower-bound'` を持ち、画面の金額を下限、ボーダーを上限として区別します。下限が負でも実際の理論期待値が負とは限りません。実機内部値・実収支の保証ではなく、時間も利用者の入力を固定した参考換算です。

リコリスは初当たり平均差玉490.84玉、LT50%、LT開始B約30%を30%に固定、A当たり後B50%を使用します。初当たりの出玉とモードの個別相関を仮定せず、平均出玉とモードの周辺分布を集計します。即時・潜伏の50%上乗せを一度だけ数えたB当たりの平均差玉は5600玉です。上乗せ終了後の通常STでのB残留率rは未確認で、0〜100%の範囲で最小のr=0を計算します。r=0を実機の仕様と主張しません。q=1−(1−1/97.1)^132、EA=q(700+0.5EA+0.5EB)、EB=q(5600+(1−r)EA+rEB)より、平均差玉490.84+0.35EA+0.15EBはrの単調増加関数です。下限は3854.9168玉。q=74.499492%と公表約75%の差も画面に明記し、75%へ置き換えません。

SAOは初回1.5%と下位当たり11%の特別当たりを最低3000個にとどめ、上位DRIVEの既知5区分97.5%だけを計上します。未確認のto BONUS1.5%・in DRIVE1.0%は確率を残して出玉を0として除外し、残りを再配分しません。上位への復帰先を保ったまま非負の出玉だけを除外するため、固定したモデルの下限になります。初回・下位のSWORD DRIVEと上位の神器解放SWORD DRIVEの分布が同じという仮定や、内部再抽選11%・5.5%の仮定は使いません。平均差玉の下限は2378.0930玉です。

公表ボーダーに合わせた逆算は禁止。正確なモデルを追加する場合は、必要な遷移と出玉を資料で確認してください。独立式、リコリスのrに対する単調性、SAOの除外出玉を戻した場合の単調性をテストしています。下限金額は1円未満切り捨て、上限ボーダーは小数第2位へ切り上げ、内部計算は丸め前の値を使います。

`dist/machine-model.mjs` は各機種に列挙した公表指標と計算値を公表の丸め幅で照合します。チェック不一致または明示的に停止されたモデルでは平均差玉をnullにし、`machineEstimate` もnullを返します。照合欄の一致はその指標についての確認で、未公表の全内部条件が確定したという意味ではありません。確率と出玉の独立式によるテストも併用します。

標準差玉は払い出しから入賞分のみを控除し、電サポ増減・こぼし・オーバー入賞は0。出玉補正で調整できます。時間の根拠がないため初期の時給は未設定です。手入力の確率・平均差玉も新規時は空欄で、利用者が確認した値を入力します（既存保存値は復元）。仕様と計算式は画面下部に記載しています。入力は同一ブラウザのlocalStorageに保存し、旧版v1は残してv2を別保存します。

GitHub Pagesは `.github/workflows/pages.yml` で公開します。公開対象は `dist/` だけで、開発ファイルやテスト、ホスティング資格情報を配信しません。計算はすべてブラウザ内で実行され、入力をサーバーへ送信しません。
